# Onkyo dahoam
Unofficial local Android controller for TX-NR656.

## v0.7.1
Two independent 1×1 volume widgets (Wohnzimmer and Esstisch). Tap opens a small real SeekBar dialog without launching the full dashboard. Android RemoteViews do not support draggable SeekBar; the tile itself is a shortcut and does not claim a live volume. The dialog checks connectivity and device profile before enabling controls, uses the existing coalesced volume commands, and never powers a zone on automatically. Widget and popup tests cover both zones.

## v0.7.0
Onkyo dahoam branding; Wohnzimmer / Esstisch labels; live volume changes sampled up to every 10 ms (network writes coalesced per zone and paced at 120 ms); relative linked +/- only while Esstisch uses SOURCE. Dashboard controls follow the reported source: FM/AM presets, NET service and transport, USB/Bluetooth transport, Google TV launcher, or a read-only SOURCE indicator. Transport uses NTC/NTZ and remains experimental on the real receiver; shared media confirmation remains in place. Existing widgets and app ID retained. Listening modes include Dolby Surround/Atmos (LMD80) and DTS Neural:X/DTS:X (LMD82); Pure Audio only when Esstisch is confirmed off. Receiver firmware, speaker layout and input format determine availability; the app shows only receiver-reported current mode.

## v0.6.1
Consistent DualZone Remote name and logo in launcher, dashboard, detail screens, both widget sizes and notifications. APK package remains at.local.dualzone. CI explicitly checks application identity, APK signature, previous debug certificate and emulator installation, plus volume controls above 50 and widget rendering. Publishes a direct APK download only after all checks pass. Debug keys are generated on hosted runners; if signing certificates differ, uninstall the older app before installation (settings and widgets are lost). Persistent private signing key requires repository secret setup; no private key is stored in the public repository. Live receiver behavior is still not confirmed.
## v0.6
Compact 1×1 scene widgets (actual minimum determined by Android launcher), with a larger layout when resized. Explicit single-zone radio ON scenes toggle off only if the real receiver confirms matching power, source and configured preset. Other scenes remain one-way. No cached state is used for deciding what to switch off. Last confirmed action has a timestamp, not a guaranteed live status. Logo uses a simplified vector rendition of the receiver-and-two-zones concept in the launcher, dashboard, configuration and compact widgets; monochrome notification icon.
## v0.5.2
Fix volume controls locking above 50. Use per-zone NRI volume limits and step scale, support two- and three-digit ISCP volume replies, and keep requested values visible until a reply or timeout. Without a positive NRI maximum, use the protocol range (100 whole units), never assume zero means a usable maximum. Volume unavailable is reported separately. The receiver's hardware maximum remains authoritative. Widget scene volumes use whole units and respect reported maxima at execution. Live volume confirmation still pending. Detail panels now follow the effective selected source: FM/AM shows tuner preset controls (receiver-reported names/frequencies when available), NET shows only the NET service selector, other sources hide both; SOURCE follows the main zone. Shared media changes require confirmation.
## v0.5.1
Widgets always show both zones' configured actions, including unchanged settings. The connection check and the last scene execution are separate. Tap refresh to perform read-only discovery and receiver status queries; it never runs the scene. Actual receiver checks are timestamped, not a claim of continuous live connectivity. Local network state updates on app/launcher refresh and on network callbacks while the process is active; Android can defer the 30-minute widget refresh while the app is closed. No periodic receiver polling or persistent foreground service. Scene failures and interruptions do not imply success. Reconfiguration resets the scene's execution history.
## v0.5
Native home-screen scene widgets, one independent configuration per widget. Set power on/off/unchanged, source, volume (0–50), optional FM/AM preset (1–40) or NET service for each zone. Explicit opt-in for shared source effects. User-initiated short foreground service performs fresh LAN discovery, verifies replies, shows success/partial failure/error on widget, never repeats a write automatically. Demo option sends no network commands. Add from Connection > Homescreen-Widgets or Android launcher; configure by tapping unconfigured widget or gear. Existing FM4 preset number must be supplied; no hardcoded frequency. Live device validation still pending. Manual IP scenes require an NRI model match. NET service selection experimental. No native TV power control. Logs remain local and capped.
## v0.4.2
A compact TV button opens the installed Google TV app via its public launcher, with a missing-app dialog. No separate TV volume control or new pairing; direct launch of Google's internal remote screen is not a supported API. The remote is also available via Android Quick Settings.

## v0.4.1
Local rotating diagnostic logs: Connection > Diagnosebericht (or tap the status). Export TXT and attach to the development chat. No automatic upload. Raw XML, IP/MAC, SSID, credentials and media names omitted. Response correlation is observational, not a transaction acknowledgement. Clear from diagnostics menu. Two files of max 128 KiB each; automatic deletion when the oldest entry is 72 hours old, checked on startup, export and logging (once per minute). Logging stops and stored logs are removed below 16 MiB available space. No background task while app is closed; expiry is checked at next launch. Exported copies are not managed by the app.

Automated JVM protocol, TCP, discovery, capability and logging tests plus Android emulator smoke test. Hardware verification pending. Test volume cap 50. Persistent signing, scenes and widgets pending.

APK from GitHub Actions artifacts. Debug signing may require uninstalling earlier versions.
